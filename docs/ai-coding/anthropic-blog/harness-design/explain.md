# Harness 设计：原文讲解

> 对应译文：[Harness 设计：长时间运行应用开发](./translation)

这篇讲解帮你理解原文中每个部分的**为什么**和**意味着什么**，而不仅仅是说了什么。

---

## 整体脉络：这篇文章在讲什么？

一句话总结：**Anthropic 团队发现，用多个 AI agent 协作（而不是一个 agent 全包）可以让 AI 自主构建出真正能用的复杂应用。**

文章的推进逻辑：

```
发现问题 → 小规模验证（前端设计）→ 大规模应用（全栈开发）→ 随模型升级简化架构
```

这不是一篇纯学术论文，而是工程师的实践报告——他们做了什么、遇到了什么坑、怎么调优的。

---

## 为什么要关注这篇文章？

这篇文章解决的不是"让 AI 写一个函数"的问题，而是：

> 给 AI 一句话描述（比如"做一个复古游戏制作器"），让它在**几小时内、完全自主**地构建出一个能用的全栈应用。

这背后涉及的技术问题，对所有做 AI 应用开发的人都有参考价值：
- 怎么管理 AI 的上下文窗口
- 怎么让 AI 评估自己的工作
- 怎么设计多 agent 协作架构

## 核心概念讲解

### 1. 什么是 Harness？

Harness 直译是"线束"或"马具"，在这里的意思是**包裹在 AI 模型外部的编排框架**。

打个比方：模型是发动机，Harness 是整辆车——方向盘、变速箱、刹车系统。发动机再强，没有这些也不能从 A 到 B。

Harness 要解决的问题：
- 什么时候该让 AI 开始工作？
- 工作到一半上下文满了怎么办？
- AI 说"做完了"，怎么验证它真的做完了？
- 多个步骤之间怎么传递状态？

### 2. "上下文焦虑"是什么？为什么重要？

这是这篇文章的一个重要观察。

**现象**：Claude Sonnet 4.5 在接近（但还没到达）上下文窗口限制时，会开始**匆忙收尾**——本来还可以继续深入的工作，模型会提前说"差不多了"。

**类比**：就像考试还剩 30 分钟，你明明还有两道大题没做，但焦虑感让你开始随便写写交卷。

**为什么压缩不够**：压缩是"在原地总结前面的对话"，但模型还是那个模型，它知道自己已经用了很长时间，焦虑感并没有消除。

**为什么重置有效**：重置是"换个新 agent 来"，新 agent 不知道之前的对话有多长，从零开始，完全没有心理负担。但代价是交接文档必须足够好。

**实际影响**：选 Sonnet 4.5 做 long task → 必须用重置。选 Opus 4.6 → 可以不用重置，直接用压缩。模型能力直接决定了你的架构选择。

### 3. 为什么要分离"做的人"和"评的人"？

**现象**：AI 给自己的作品打分，几乎总是给高分。就像让学生给自己批作业——99% 会给自己满分。

**为什么单独调优评估器更可行**：
- 让生成器自我批评 → 本质上是在跟模型的"讨好倾向"对抗，很难
- 单独做一个评估器 → 只需要让这个评估器学会"挑毛病"，然后把它调到足够挑剔就行

**GAN 的类比**：
- GAN 中：生成器造假，判别器打假，两者对抗都变强
- 这里：生成器写代码，评估器找 bug，循环迭代产出更好结果

### 4. 四个评分标准的设计思路

这四个标准的设计很有讲究：

| 标准 | 解决什么问题 |
|------|-------------|
| 设计质量 | 防"拼凑感"——各个部分看起来不像一个整体 |
| 原创性 | 防"AI 套路"——紫色渐变、白色卡片这些 AI 的"安全牌" |
| 工艺 | 基本功底线——间距、排版、对比度这些 |
| 功能性 | 可用性底线——用户能不能用 |

**权重设计**：设计和原创性权重更高。为什么？因为 Claude 在工艺和功能上本来就不差，你不需要特别强调。它弱的是审美和创意，所以要重点推。

**这给了我们一个通用方法论**：评估标准不是越多越好，而是要**针对模型的薄弱环节加权**。

### 5. Sprint 合同机制——这篇文章最精妙的设计

```
生成器提议 → 评估器审查 → 双方达成一致 → 开始编码 → 按合同验收
```

**为什么需要这一步？**

因为规划器给的规格是高层级的（用户故事级别），而编码需要的是具体实现细节。中间需要一个"翻译"步骤。

类比软件开发：
- 规划器 = 产品经理写 PRD
- Sprint 合同 = 开发和 QA 一起开评审会，对齐"完成标准"
- 生成器 = 开发写代码
- 评估器 = QA 测试验收

**关键洞察**：合同是在编码之前协商的。这意味着评估器不是在"找茬"，而是在验证双方事先约定好的标准。这让评估更客观、更可执行。

### 6. Harness 简化的核心思想

这是文章最有价值的洞见之一：

> **Harness 中的每个组件都编码了一个假设："模型自己做不到这件事"。**

所以当模型升级后，你要做的事情是：

```
1. 逐个移除组件
2. 看哪个移除后结果变差 → 那个是"承重墙"，不能拆
3. 看哪个移除后没影响 → 那个假设已过时，可以删
4. 利用新能力添加新组件
```

他们就是这么做的：Opus 4.6 更强了 → 移除 sprint 分解 → 结果仍然好 → 说明 sprint 分解对 4.6 不再是承重墙。

### 7. 评估器"是否需要"的动态判断

```
任务难度谱：
简单 ←────────────────────────────────→ 复杂
      ↑ 模型可靠独立完成        ↑ 模型仍需要外部检查
      评估器 = 不必要的开销      评估器 = 值得投入的成本
```

**关键点**：这条分界线不是固定的，它随着模型能力提升向右移动。

- 对于 Opus 4.5：很多任务在这条线的右边，评估器非常有价值
- 对于 Opus 4.6：同样任务移到了线的左边，评估器变成了开销
- 但对于更难的任务：评估器仍然在右边，仍然有价值

**实际指导意义**：不要机械地加或删评估器，而是要根据**你的任务难度**和**你用的模型**来判断。

## 文章背后的思维模型

### 思维模型一：AI 工程的本质是"脚手架管理"

```
模型能力 ════════════════════════════════► 不断提升
任务需求 ════════════════════════════════► 不断变难
                ↑
           差距 = Harness 要弥补的空间
```

Harness 的价值 = 任务需求 - 模型能力。模型越强，你需要的 Harness 越简单。但如果你想用更强的模型做更难的事，Harness 的价值又回来了。

### 思维模型二：迭代胜过一次性生成

不是让 AI 一次做到完美，而是设计一个循环：
```
生成 → 评估 → 反馈 → 改进 → 再生成 → ...
```

5-15 轮迭代后，质量远超单次生成。成本更高，但结果也更好。

### 思维模型三：具体标准胜过模糊指令

"做得好看" → AI 产出平庸结果
"符合这 4 个具体标准，权重分别是 3:3:2:2" → AI 产出明显更好的结果

## 实验数据解读

### 游戏制作器实验

| | 单 Agent | 三 Agent Harness |
|---|---|---|
| 成本 | $9 | $200（22 倍） |
| 时间 | 20 分钟 | 6 小时（18 倍） |
| 核心功能 | 坏的（游戏不能玩） | 能用（有粗糙但可玩的物理） |

**解读**：22 倍的成本换来了"从不能用变成能用"。值不值？取决于场景——如果是原型验证，可能不值得；如果是让非技术人员也能构建应用，可能很值得。

### DAW 实验

总成本 $124.70，3 小时 50 分钟。构建器连续运行 2 小时没崩溃（这本身就是 Opus 4.6 能力的证明）。

**解读**：注意成本结构——构建占了 91% 的成本和时间，规划器和 QA 很便宜。所以优化 harness 的重点不在规划器和 QA，而在构建器的效率。

## 可以从中学到什么？

1. **如果你在构建 AI 应用**：考虑多 agent 架构，尤其是需要"自我检查"的场景
2. **如果你在用 Claude Code 做长任务**：理解上下文管理的两种策略（压缩 vs 重置），根据模型选择
3. **如果你在设计评估系统**：把主观标准转化为具体、可评分的维度，并针对薄弱环节加权
4. **如果你在跟进 AI 发展**：关注 Harness 设计的演化——它反映了模型能力的边界在哪里

## 关键术语速查

| 英文 | 中文 | 一句话解释 |
|------|------|-----------|
| Harness | 编排框架 | 包裹在模型外部的任务管理系统 |
| Context Anxiety | 上下文焦虑 | 模型在接近上下文限制时提前收尾的倾向 |
| Context Reset | 上下文重置 | 换新 agent 接手，通过文档传递状态 |
| Compaction | 压缩 | 在原地总结早期对话，不换 agent |
| Sprint Contract | Sprint 合同 | 编码前双方协商好的验收标准 |
| Evaluator | 评估器 | 专门负责检查另一个 agent 工作的 agent |
| Few-shot Calibration | 少样本校准 | 用几个标好的例子调整评估器的打分标准 |

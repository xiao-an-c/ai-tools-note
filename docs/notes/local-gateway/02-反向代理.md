# 反向代理是什么

## 一句话解释

反向代理就是一个"中间人"——你访问 `stock.d.me`，反向代理帮你转发到真正的服务 `localhost:1010`。

## 正向代理 vs 反向代理

容易混淆的两个概念：

```
正向代理：代理的是【客户端】
  用户 → 代理服务器 → 目标网站
  （翻墙就是正向代理，网站不知道你是谁）

反向代理：代理的是【服务端】
  用户 → 反向代理 → 后端服务1 / 后端服务2
  （你不知道真正处理请求的是哪台服务器）
```

我们的方案是**反向代理**。

## 为什么需要反向代理

没有反向代理时：

```
http://localhost:1010   → 股票系统
http://localhost:1001   → NewAPI
http://localhost:3000   → 前端项目
http://localhost:8080   → 后端 API
端口太多了，记不住
```

有反向代理后：

```
http://stock.d.me      → 股票系统
http://newapi.d.me     → NewAPI
http://app.d.me        → 前端项目
http://api.d.me        → 后端 API
全部走 80 端口，用域名区分
```

## Nginx Proxy Manager 做了什么

NPM 本质上就是在帮你自动生成 nginx 配置文件。你通过 Web UI 添加一条规则：

```
域名: stock.d.me  →  转发到: host.docker.internal:1010
```

NPM 会在后台生成类似这样的 nginx 配置：

```nginx
server {
    listen 80;
    server_name stock.d.me;

    location / {
        proxy_pass http://host.docker.internal:1010;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

含义：

- `listen 80` — 监听 80 端口
- `server_name stock.d.me` — 匹配这个域名的请求
- `proxy_pass` — 转发到后端地址
- `proxy_set_header` — 把客户端信息传递给后端

## host.docker.internal 是什么

NPM 跑在 Docker 容器里，容器内的 `localhost` 指的是容器自己，不是你的 Mac。

```
Mac 本机
├── localhost:1010  ← 股票系统跑在这里
└── Docker 容器
    └── localhost   ← 指向容器内部，不是 Mac！
```

Docker Desktop 提供了 `host.docker.internal` 这个特殊域名，容器内用它就能访问 Mac 本机的服务：

```nginx
proxy_pass http://host.docker.internal:1010;
# 容器内通过这个地址访问 Mac 的 1010 端口
```

## 请求完整流程

```
浏览器访问 http://stock.d.me
  ↓
DNS 解析: stock.d.me → 127.0.0.1
  ↓
连接 127.0.0.1:80（Nginx Proxy Manager 监听的端口）
  ↓
NPM 根据 server_name stock.d.me 匹配到对应规则
  ↓
转发到 host.docker.internal:1010（Docker 容器内访问 Mac 本机）
  ↓
Mac 的 1010 端口（股票系统）处理请求并返回响应
  ↓
NPM 把响应返回给浏览器
```

## 反向代理的其他用途

除了简化域名，反向代理还常用于：

| 用途 | 说明 |
|------|------|
| 负载均衡 | 一个域名分发给多台服务器 |
| SSL 终端 | 统一处理 HTTPS 证书 |
| 缓存加速 | 缓存后端响应，减轻压力 |
| 安全隔离 | 隐藏后端真实地址 |

我们目前只用到了"简化域名"这个功能。
